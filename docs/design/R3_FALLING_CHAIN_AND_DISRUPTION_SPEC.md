## 현재 추가 결정 — 2026-09-20 시동 문양과 연쇄 완성 스킬

사용자의 플레이 후 피드백과 이어진 권장안 승인을 반영한다. **선택형 자원 전투에서만** 아래 규칙이 이전 수동 ATK/DEF/SUP 선택과 파동별 발동을 대체한다. 자원 확보 LINE/SWAP 선택, 유한 낙하쌍 보급, 문양별 자원 효과와 승인 자산은 유지한다. 이전 R3/원정 실행은 호환성 경로이며 새 규칙을 적용했다고 표시하지 않는다.

- 첫 플레이어 소거의 시동 A/D/H/T가 공격/방어/치유/시간 스킬을 결정한다. 같은 첫 파동에 여러 문양이 터지면 이번 낙하쌍의 회전축 셀을 포함한 소거 → 문양별 소거 수 최다 → 가장 위 행, 같은 행은 왼쪽 셀 순으로 판정한다. 배열 순서·프레임 속도와 무관하다. 현재 착지로 시작할 문양을 예고한다.
- 이후 파동은 시동을 바꾸지 않으며 연쇄 전체가 안정화된 뒤 **단 한 번** 발동한다. 적 파괴가 만든 정산은 시동·콤보·스킬을 만들지 않는다. 적 파괴로 플레이어 연쇄가 끊겨도 이미 완료한 플레이어 파동은 보존하고, 적 정산까지 안정화된 후 해당 파동만 한 번 계산한다. 패배 시 미발동 기술은 취소한다.
- 공격/치유는 기존 파동별 기본 위력을 합한다(공격 3연쇄=4+6+8=18). 공격 자원은 접촉 시점에 한 번만 소모한다. 방어는 마지막 단계의 최대 보호 수치와 현재 피해 행동 대상 제한을 유지한다. 시간은 T1~T6=0.25/0.5/0.75/1/1.25/1.5초이며 자원 시간 보너스와 **현재 적 행동당 총 3초 상한**을 공유한다. 확정된 공격을 취소하거나 다음 행동으로 잔여를 넘기지 않는다.
- 연쇄 정산 자체는 기존 공유 시간 흐름을 유지한다. 연쇄 완성 후 플레이어 연출 1.4초(4연쇄 이상 2초), 적 행동 연출 1.6초. 플레이어 접촉 0.5초/적 접촉 0.6초에 실제 효과 1회 적용. 연출 동안 **양쪽 보드·공유 ETA·보급 조작 모두 정지**한다. 적과 연쇄가 같은 순간이면 적 확정 행동이 먼저다. 이 정지는 시간 문양 보상이 아니다. 일시정지/포커스 상실은 연출 시간도 멈춘다.
- UI는 수동 스킬 버튼을 제거하고 시동 예고/확정, T1~T6 진행, 합산 위력, 최근 발동과 연출 중 양쪽 정지를 표시한다. 시간 기술은 기존 지원 캐릭터 포즈와 시간 문양을 재사용한다. 새 이미지/최종 자산 승인을 주장하지 않는다.
- owner: `data/replanned_r3/finisher.json` → `r3_finisher.gd`(선택·산술), `r3_finisher_session.gd`(순서·접촉·검증), `resource_choice.tscn`/`r3_screen.gd`(실제 화면). 기존 `r3_session.gd`는 기본 규칙을 보존하는 작은 확장 지점만 제공한다.
- 저장은 `user://starter_finisher/save.json`, schema `r3-finisher-v1`/`r3-finisher-choice-v1`. 기존 `user://resource_choice/`, R2, legacy R3는 덮거나 암묵 변환하지 않는다. 연쇄/연출 중 저장 불가; 안정화 후 소거 원장·발동 이력·규칙 hash를 교차 확인하고 복원해도 재발동하지 않는다.

재미 가설: 별도 메뉴 선택 없이 놓는 문양이 전투 선택이 되고, 연쇄 완성의 한 번 큰 기술이 읽히며 보람을 준다. 반례: 첫 문양을 예측하지 못함, 혼합 소거 결과가 임의적으로 보임, 긴 연출로 반복 피로, 시간/치유 시동만 강요됨. 기계 검증(결정성·중복·경계·저장), 실제 화면 검증(예고/연출/ETA), 사람 플레이 관찰(의도 설명·속도·반복 피로)을 구분한다. 사람 재미/수치 최종 검수는 **NOT_RUN**. 비교한 대안은 파동별 발동 유지 REJECT(최신 지시와 충돌), 마지막 단계 수치만 지급 REJECT(공격·치유 암묵 하향), 누적 공격·치유/최대 방어 ADAPT(선택). 진행/증거: `docs/operations/STARTER_FINISHER_EXECUTION.json`.

## 2. 현재 문제의 확인 수준

`r2_chain.gd::commit_wave`는 소거 빈칸을 새 문양으로 채우고 다음 매치를 계속 처리한다. `r2_session.gd::command(chain_swap)`에는 LINE에서 확보한 공급량을 요구하는 조건이 없다. 따라서 CHAIN 자체가 스킬 발동 기회를 계속 공급한다. 실제 코드로 확인한 구조적 문제다.
현재 원정 테스트 드라이버 또한 LINE 줄 소거 없이 CHAIN 명령으로 승리 경로를 만든다. 다만 이 드라이버는 생각 시간이 0인 합법 수 탐색이므로 **인간의 승률·초당 피해량 우월성이 실측됐다는 증거는 아니다**. 사용자 체감과 코드상 무한 발동 가능성이 방향 변경의 근거이며, 정량 우월도는 새 비교 시험으로 측정한다.

| 대안 | 장점 | 문제/장기 비용 | 판정 |
|---|---|---|---|
| A 교환 보드 유지, 스킬 수치만 약화 | 저비용 | 사용자 변경과 다름. 무한 공급과 역할 중복 유지 | REJECT |
| B 낙하 연결로 변경, 낙하쌍 무한 공급 | 직접 연쇄를 설계하는 재미, 새 재화 없음 | 숙련 CHAIN 단독 전략을 구조적으로 막지 못함 | 비교군으로 보존 |
| C 낙하 연결 + LINE 소거로 낙하쌍 보급 | LINE 준비와 CHAIN 실행이 실제 의존 관계 | 보급 대기/강제 숙제 위험, 수치 검증 필요 | 권장 상세안 |

공급 횟수는 다섯 번째 타일 종류나 구매 재화가 아니라 **다음에 놓을 수 있는 조각 수**다. 숨기지 말고 NEXT 근처에 표시한다. 시간제 강제 전환이나 스킬 전면 쿨다운은 추가하지 않는다.

## 4. R3-CHAIN: 낙하 연결 보드

### 보드와 조작

- 6열×12가시행+숨김2행. 빈칸은 EMPTY, 색은 A/D/H/T. 초기 보드는 비어 있음.
- 한 조각은 축과 위성 두 셀. 축 spawn=(2,-1), 위성=(2,-2); 가시 좌표 y=0..11, 숨김=-2,-1.
- 좌/우 이동, 아래 soft drop, 시계/반시계 90도 회전, 즉시 낙하. LINE과 공통 키 재사용. CHAIN의 HOLD는 첫 범위에서 없음; NEXT는 다음 두 쌍 표시.
- 90도 회전의 후보 offset 순서 (0,0),(-1,0),(1,0),(0,-1). 처음 충돌하지 않는 후보 적용, 전부 충돌이면 무효. 180도/원작 퀵턴은 미포함. 천장 밖 회전 불가.
- 활성 중 중력은 700ms당1행, soft drop50ms당1행, 접지 확정500ms, 이동/회전 잠금 리셋 최대8회. 성공한 이동/회전만 리셋. hard drop은 즉시 확정. 모두 시험값.
- 두 셀이 착지한 뒤 각 열 안에서 아래로 정렬한다. 수평 조각 한쪽 밑이 비어 있으면 해당 셀만 떨어진다. 그 이후 연결 판정.
- 같은 문양이 상하좌우로 연결된 집합4개 이상 소거. 직선일 필요 없음(L/사각형도 성립). 대각선은 연결하지 않음.
- 같은 검사에서 성립한 모든 집합은 하나의 파동. 예: A4와D4 동시 소거도 C1/스킬1회.
- 소거 후 남은 셀만 아래로 낙하. **빈칸에 자동 보충하지 않는다.** 다음 낙하쌍만 새 셀의 공급원.
- 한 파동300ms(소거 예고180+낙하120)의 고정 논리 시간. 낙하 높이·렌더 FPS·효과 축소에 따라 발동 시점을 바꾸지 않음. 최대 연쇄21회 안전상한(총84셀/4); 초과 상태는 에러로 정지하고 진단하며 자동 보상/재생성 금지. 매 파동 최소4셀 감소와 신규보충0도 검사한다.
- 안정화 후 숨김행에 셀이 남거나 다음 spawn 두 칸이 막혀 있으면 CHAIN 넘침: HP25 직접 손실, CHAIN 보드만 비움. 낙하쌍·공격 bank·LINE 배치는 환급/리필하지 않음. 실제 HP0이면 패배. 판정은 소거가 살릴 기회를 준 뒤 한 번만.

### 전환·시간·선택

- 활성 낙하쌍 중 전환 가능. 위치/방향/중력·접지 잔여시간 보존, 비활성 보드는 낙하하지 않음. 숨겨 두어도 적 ETA는 진행.
- 연쇄 해소 중 전환은 기존 R2처럼 안정화까지 예약. 선택 계열은 **착지 확정 시** 저장하고 그 착지에서 이어지는 모든 파동에 동일 적용.
- 떨어지는 중에는 계열 변경 가능. 파동 시작 후에는 변경 불가. T단계 클릭은 설명만, 계열/배치/공급을 바꾸지 않음.
- 논리 상태: NEED_PAIR → FALLING → LOCKED_SETTLE → CLEAR_PENDING → FALL_SETTLE → (CLEAR_PENDING 또는 NEED_PAIR). DISRUPTION_SETTLE은 별도 원인 상태. PAUSED는 직교 flag.
- 다음 pair를 spawn할 때 공급1쌍 소비. spawn 불가 시 공급 차감 전에 넘침 판정. 이미 spawn된 pair는 전환/저장/피격으로 다시 차감하지 않음.

### 스킬

R2 ATK[4,6,8,11,14,18], DEF[3,5,7,10,13,17], SUP[2,3,4,5,7,9]를 첫 비교의 기준값으로 유지. 새 퍼즐 때문에 이후 재조정 가능하나 처음부터 공급·스킬·보스 HP를 모두 바꾸지 않는다.
T=min(파동번호,6). C7 이후 T6 유지. 안정화 시 연쇄 깊이0. 네 색은 CHAIN에서 연결 조건일 뿐 직접 자원 보상은 없음.
ATK는 단계값+준비 bank를 한 번 적용하고 bank0. DEF는 현재 미확정 적 행동의 방벽 목표치 max 갱신. SUP는 HP 상한까지 회복. 잘못된 입력·스폰·단순 낙하·적 파괴는 자동 스킬을 만들지 않음.

## 5. R3-SUPPLY: LINE↔CHAIN 연결 권장안

초기 잔여4쌍, 최대12쌍. 실제 플레이어 LINE 소거의 고유 셀10개당+3쌍(정상 1줄10개). 동시에4줄이면+12쌍, 저장 상한 초과는 버림/명시. 향후 부분 소거를 대비해 누적 remainder0..9를 저장하되 적 파괴는 이 누적에 넣지 않는다.
LINE 기존 보상 A→다음 공격+1, D→방어도+1, H→HP+1, T→현재 미확정 ETA+0.25초(행동당+3초)는 그대로다. 공급량은 문양과 무관하므로 특정 색을 기다릴 필요 없음.
공급0이고 활성 pair 없음: CHAIN 입력 배치만 비활성, '낙하쌍 0 · LINE 한 줄로 3쌍 보급' 표시. 강제 전환하지 않고 LINE 버튼을 강조. 적 ETA는 진행한다. 자원 공급이 없는 상태에서 무료 pair/무료 skill/시간 정지를 주지 않는다.
색 생성은 A,D,H,T 각2개의8셀 bag을 섞어 두 셀씩 묶는다. 공급을 얻을 때가 아니라 NEXT 큐 생성 시 색을 결정. 큐·bag·RNG 상태 저장. 전환/재개/보급 상한으로 재추첨하지 않음. 초깃값은 불리한 확률 보정이 없는 균등 분포다.
전투 종료 후 남은 공급과 CHAIN 배치는 이월하지 않음. 다음 전투4쌍/빈 보드. 원정 HP/방어/공격 준비의 현재 이월 규칙은 유지.

예: 잔여2쌍, LINE에서 A6/D4 한 줄 → bank+6/방어도+4/잔여5쌍. CHAIN 다음 pair spawn →4쌍. 두 번 연쇄 ATK → 첫4+bank, 둘째6. 적이 D3개를 파괴해도 방어도·공급 모두0 증가.
비교 시험에서 보급 이동이 숙제처럼 느껴지면 1줄당3→4쌍 또는 cap12→16을 먼저 비교한다. 무료 자동 보충으로 회귀시키거나 별도 MP까지 추가하지 않는다. 초기4쌍만으로 모든 적을 잡지 못한다는 수학적 보장과 게임의 재미는 구분한다.

## 6. R3-DISRUPT: 적의 무작위 블록 파괴

### 표적과 예고

- 해당 행동이 Current가 되는 순간 활성 보드 ID를 고정. 이후 전환해도 대상 보드는 바뀌지 않음. 비활성 대상은 보드 탭에 표적 수 표시. 둘 다 파괴하지 않음.
- 마지막2초 진입 시 대상 보드의 **고정된 일반 셀**에서 중복 없이 n개를 무작위 선택. 활성 조각, 고스트, HOLD/NEXT, 이미 소거 확정된 셀은 제외. 대상 부족이면 실제 수만 선택. 0개면 보드 효과0, HP 공격은 정상 실행.
- 좌표가 아니라 불변 cell_id를 예약. 표식은 이동하는 셀 ID를 따라가고 플레이어가 먼저 소거한 셀은 빗나감. 다른 셀로 재선정하지 않음. 시간 연장 후에도 같은 표적.
- seed는 run_seed와 action_instance_id에서 별도 RNG stream 생성. LINE/CHAIN 조각 RNG를 소비하지 않음. pause/저장재개로 바뀌지 않음.
- Current 카드에 'HP 피해 / [대상 보드] n개 파괴 · 파괴 보상 없음'. 실제 선택 전에는 대상 보드/최대수만, 선택 후에는 확정 수와 표식. 소리와 색만으로 알리지 않음.

### 실제 처리

같은 시각: pause 요청 → 적 행동 commit/HP 피해 → 플레이어 사망 판정 → 살아 있으면 적 파괴 → 플레이어 착지/소거/스킬. 현재 파동의 소거 셀은 소거 예약 시 보호하여 이미 약속한 파동과 표적을 겹치지 않게 한다.
연쇄 도중 ETA가 끝나면 HP 피해는 지연하지 않음. 보드 파괴는 현재 파동의 원자적 처리 뒤에 적용하고 다음 파동 검사보다 앞선다. 보호 셀은 표적 선정에서 제외했으므로 중복 소거 없음. 대기하는 파괴 이벤트를 저장한다. 스킬로 적이 사망해도 이미 commit된 파괴 이벤트는 살아 있는 플레이어 보드에 한 번 적용; 미확정 행동만 취소.
파괴 이벤트 cause=ENEMY_DESTROY: 직접 자원0, 보급0, 스킬0, 점수0. 파괴로 새 연결이 생긴 후속 정리도 cause=ENEMY_SETTLE를 유지해 무보상. 플레이어 연쇄는 이 개입 경계에서 종료하며, 이전까지 확정된 스킬을 취소하지 않는다.
LINE에서는 셀만 빈칸으로 바꾸고 개별 셀 중력은 적용하지 않는다. 자연 소거로 가산하지 않는다. CHAIN에서는 생존 셀 낙하→4연결 무보상 정리를 안정화까지 진행. 상한/원인 구분 적용. 활성 낙하 pair는 파괴 정리 중 제자리·타이머 동결 후 계속(그동안 적 전투 시간은 정상). 새 자동 pair는 정리 뒤 한 번만 spawn.

### 방어와 역효과

일반 방어도/DEF 방벽은 **HP 피해만** 막고 파괴 개수는 줄이지 않는 첫 비교안. '방어로 완전히 막았다'라는 문구는 보드 파괴가 남으면 사용 금지. 대응은 예고 셀 선소거/연쇄 선발동/시간 연장/처치/다른 보드에 대비된 배치 사용이다. 파괴 전용 방패 스킬은 첫 범위에서 추가하지 않음.
블록을 없애면 높이가 낮아져 유리해질 수 있다. 따라서 모든 파괴를 항상 손해라고 주장하지 않는다. 사용자 요청대로 파괴를 유지하되 일반 피해와 함께 드물게 사용하고, 구축 중인 연결/LINE 채움의 손실을 노린다. '파괴 공격이 오히려 기대 보상'이라는 시험 결과가 나오면 대상 선택/빈도를 수정한다. 임의 자원 압수·방해 블록 추가로 몰래 의미를 바꾸지 않음.

### 첫 콘텐츠 시험값

| 적/행동 | 현재 수치 | R3 제안 | 목적 |
|---|---|---|---|
| 외곽 균열 | 12초/6,16초/16,12초/6,8초/0 | 파괴 없음 | 두 보드 보급·연쇄 학습 |
| 감시탑·파편 사격 | 7초/7 | 유지 | 일반 견제와 구분 |

| 주조소·주조 붕괴 | 16초/26 | HP26 + 무작위3셀 | 느린 구축 파괴 |
| 균열 핵·균열 분쇄 | 14초/35 | HP35 + 무작위4셀 | 최종 종합 대응 |

다른 행동·적 HP는 기준값 유지. 완화 모드는 현재 피해/ETA 완화 규칙을 유지하고 파괴 수 max(1,n−1). 마지막2초 표적 예고는 더 줄이지 않음. 난이도 효과는 데이터와 계산된 예고가 일치해야 한다.

## 7. 데이터·저장·화면 계약

구현 후보 이름은 R3로 분리한다. `data/replanned_r3/rules.json`이 위 수치의 단일 기계 정본, 이 문서는 의미/AC 정본. 원작 이름은 내부 비교 문맥에서만; 화면은 'CHAIN · 낙하 연결' / 조각은 기존 세계관 문양의 '룬 쌍' 권장.
새 스냅샷 `r3-session-v1`: rule_pack_hash, run_id, seed, active_workspace, elapsed_us, selected_category, 기존 HP/bank/armor/ward, LINE상태, chain_state, supply_pairs/remainder, pending_disruptions, processed_event_ids.
chain_state: 6×14 고정 셀(cell_id,kind), 활성 pair(id,axis,satellite,orientation), gravity/lock 잔여, lock_reset_count, NEXT2/bag/RNG, phase, chain_id/wave_index/category_snapshot, 예약 소거 ID, 파동 잔여, cause. 처리 순서와 RNG stream version도 저장.
LINE도 문양 격자와 동일 크기의 셀 ID 격자를 가진다. R3 어댑터가 착지/줄 압축/부분 파괴를 원자적으로 동기화하고, 아래 줄이 소거되어 표적이 내려가도 ID는 유지한다. 전투별 namespace와 단조 증가 ID 카운터를 저장하며 제거된 ID는 재사용하지 않는다. 구형 R2 LINE 규칙의 재사용은 ID 추적까지 이미 구현됐다는 뜻이 아니다.
R2 저장을 R3 보드로 자동 변환하지 않음. 별도 `user://replanned_r3/`와 새 원정 envelope. R2 이어하기는 R2 실행 경로에서만 제공/보존, R3 메뉴에서 명시. 손상/다른 rule hash는 fail closed+백업 복원, 임의 초기화 금지. 안정 상태만 신규 체크포인트; 진행 중은 직전 안정 체크포인트 유지. pause 후 복원은 항상 paused.
같은 action/cell/clear/pair_spawn ID 중복 처리 금지. 공격 예약은 저장 시 원래 셀 ID와 연결, 재선정 금지. 모든 실패는 변화 전 스냅샷을 유지해야 함.
