# Tetris 프로젝트 · 새 기획 사람용 블루프린트

Publication ID: TETRIS-REPLAN-HUMAN-01. 2026-09-11. 최종 사용자 검토용 권장안.
이 파일은 REPLAN-043의 사람용 통합 설명과 새 화면·첫 완결 세션·제작 인계 상세를 소유한다. 기존 R1 규칙의 책임 원본은 REPLANNING_RULES_AND_FUN_SPEC.md, 비교 실험의 수치·예약 규칙 원본은 REPLANNING_FOUNDATION.md §10이다. 아래 규칙 표는 이들 원본을 읽기 쉽게 표현한 요약이며 별도 밸런스 정본이 아니다. 충돌하면 원본부터 교정한다.
현재 게임 코드는 변경하지 않는다. 시각자료는 새로 생성한 게임 사용 후보이며 사용자 승인·게임 연결·실행 검증을 아직 받지 않았다. 이전 블루프린트는 보존한다. 십보강호 PDF는 편집 구조 참고만 사용한다.

## 01 · 두 개의 준비, 하나의 위협

@asset R1-ENV full 620 270

LINE에서 힘을 모으고, CHAIN에서 증폭을 준비한다. 다가오는 보스의 공격을 읽고, 지금 공격할지 막을지 회복할지 결정한다.

게임의 표지는 직업 이름이 아니라 이 경험을 설명해야 한다. 현재 문서의 Tetris는 저장소 식별명이며 상용 게임 제목 확정이 아니다. 뱅가드는 첫 플레이어 역할이다. 이전 대화만으로 제목·로고 승인을 복원하지 않는다.

이번 책의 목표는 “그럴듯한 그림이 있는 기획”이 아니라, 읽은 사람이 선택의 이유를 이해하고 구현 담당자가 정상·실패·취소까지 같은 뜻으로 구현할 수 있는 준비 상태다.

## 02 · 화면 아틀라스 — 한 세션을 찾는 지도

@atlas

메인 → 전투 안내 → LINE/CHAIN 전투 → 일시정지한 스킬 판단 → 승패와 복기 → 다시 도전. 설정·도움말은 상태를 보존하고 원래 화면으로 돌아온다.

이 아틀라스는 실제 후보 이미지와 수정 가능한 화면 배치 정보로 만든 설계도다. Godot 실행 캡처가 아니다. 이미지 파일은 따로 게임에 사용할 수 있고, 글자·수치·버튼은 게임 UI가 그린다.

## 03 · 읽는 순서와 최종 승인 범위

| 먼저 알고 싶은 것 | 읽을 부분 | 판단할 질문 |
| --- | --- | --- |
| 어떤 게임인가 | 04~12 경험·SWOT·비교·전체 흐름 | 두 보드를 오가는 이유가 납득되는가? |
| 실제로 무엇을 누르는가 | 13~22 화면·입력·시간 | 화면마다 진입·선택·취소·복귀가 명확한가? |
| 규칙은 어떻게 작동하는가 | 23~32 보드·경제·스킬·보스 | 표시한 효과와 실제 판정이 같은가? |
| 처음 배우고 다시 하는 방법 | 33~36 교육·난도·복구·음향 | 실패해도 이유를 이해하고 다시 시도할 수 있는가? |
| 어떤 그림과 동작을 쓰는가 | 37~42 아틀라스·상태·모션 | 실제 칸에서 얼굴·문양·위협이 읽히는가? |
| 바로 구현하려면 | 43~48 데이터·경계·검수·인계 | 구현 순서와 완료 증거가 빠짐없는가? |

승인은 R1 첫 완결 세션과 이 책에 포함한 시각 후보의 방향을 대상으로 한다. 영구 성장·추가 직업·장편 캠페인·상점·과금·출시는 포함하지 않는다. 이를 숨은 미완성으로 남기지 않고 확장 보류로 명시한다. 최종 승인 후에도 재미·최종 밸런스·접근성은 실제 플레이로 검증한다.

첫 구현의 지원 대상은 Windows PC·키보드/마우스, 최소1280×720이다.1920×1080은 동일한 논리 화면을 비례 확대한다. 게임패드·터치·모바일 대응을 이번 완료 범위로 암묵적으로 추가하지 않는다. 이 책의 신규 상세·제작용 데이터는 권장안이며 기존 R1 규칙/비교 실험과 현재 실행 버전은 각각 원래 책임 원본을 유지한다.

## 04 · 플레이어가 얻어야 할 경험

| 경험 의도 | 실제 선택 | 눈에 보여야 할 결과 | 실패 신호 |
| --- | --- | --- | --- |
| 내가 조작했다 | 안전한 한 줄과 위험한 큰 지우기 중 선택 | 지운 줄 → MP 증가가 연결됨 | 왜 자원이 늘었는지 모름 |
| 준비가 남는다 | 완성 직전 보드를 두고 다른 보드로 전환 | 복귀했을 때 배열·활성 조각이 그대로 | 전환을 리셋이나 강제 숙제로 느낌 |
| 읽어서 뒤집었다 | 치명타를 막거나 먼저 처치 | 예고했던 피해와 방어량·처치가 일치 | 기술을 눌러도 결과가 예상과 다름 |
| 다음을 위해 남긴다 | 지금 기본 기술, 다음 위협에 증폭 | 남은 증폭이 다음 선택을 바꿈 | 언제나 증폭 버튼만 누름 |
| 숙련이 쌓인다 | 짧은 대응과 큰 준비를 상황에 맞춰 조절 | 낭비·피해·선택 이유를 복기 | 점수만 늘고 판단은 같음 |

독창성은 두 퍼즐의 조합 자체가 아니다. “서로 보존되는 준비 상태를 같은 위협 시간에 맞춰 배분하는 과정”이 이 게임의 정체성 가설이다. CHAIN을 빼도 판단이 거의 같다면 이 가설은 실패한 것이다. 그림·명칭·메뉴 수로 실패를 감추지 않는다.

## 05 · SWOT — 강점을 어떻게 강화할 것인가

| 강점과 현재 근거 | 강화 방법 | 기대효과 | 반증·유지 기준 |
| --- | --- | --- | --- |
| 두 보드의 상태 보존·결정적 생성이 기존 구현에 있음 | 전환 전후 보드·조각·난수 상태를 같은 기록으로 검증 | 작은 준비가 다음 계획에 이어짐 | 전환으로 한 칸이라도 임의 변화하면 출시 차단 |
| 예고와 전술 일시정지·확정 거래가 있음 | 하나의 ETA를 큰 숫자와 현재 행동 카드에 연결 | 퍼즐 숙련이 달라도 판단할 시간을 확보 | 정지 중 ETA·상태가 변하면 심각 결함 |
| LINE의 HOLD·고스트·7-bag를 재사용 가능 | 기존 조작감을 고정한 비교부터 시작 | 새 경제의 효과를 입력 퇴행과 분리 | 조작 변화가 필요하면 별도 설정·실험으로 분리 |
| 공격·방어·회복의 목적이 직관적 | 그림과 이름은 유지하고 증폭은 같은 효과만 강화 | 기술 설명과 아이콘 제작량 감소 | 높은 증폭에서 전혀 다른 기술이면 R1 위반 |

강점은 코드 존재에 대한 판단이다. 플레이어가 그것을 즐긴다는 뜻은 아니다. 첫 노출 관찰에서 “왜 바꿨는가”와 “무슨 일이 일어날 것으로 생각했는가”를 답변 전에 기록한다. 체감 증거가 약하면 구조를 보존한 채 설명·경제·위협 관계부터 수정한다.

## 06 · SWOT — 약점의 원인과 개선 순서

| 약점 | 원인 가설 | 우선 조치 | 기대효과·부작용 | 확인 방법 |
| --- | --- | --- | --- | --- |
| 시선이 좌우로 분산됨 | 조작 보드와 피해 예고를 함께 읽음 | 50:50 조작/전투, 보스 아래 ETA 고정, 장식 밝기 제한 | 위협 탐색 비용 감소; 거대한 보스와 정보 면적 충돌 가능 | 실제 크기에서 현재 공격·남은 시간 찾기 |
| CHAIN을 쓰지 않거나 의무로 느낌 | 추가 증폭 가치가 준비 시간에 비해 약하거나 모든 생존에 필수 | MP가 넉넉한 경우·부족한 경우·큰 위협을 구분한 시나리오 | 상황별 선택; 수치만 올리면 강제 비용이 될 위험 | 보드별 시간·전환 이유·무시 전략 결과 |
| 스킬 창 반복이 피로함 | 즉시 재개 후 연속 사용에 여러 클릭 필요 | 세 목적 고정, 기본/증폭 비교, 명확한 키보드 포커스 | 선택 경로 단축; 즉시 자동 발사는 금지 | 활성 시간과 메뉴 체류를 따로 측정 |
| 생성 그림의 규격이 흔들림 | 요청한 크기·여백과 실제 출력이 다름 | 실제 크기·영역·원본 해시 기록, 작은 칸 검수 | 전체 시트를 얼굴 칸에 넣는 퇴행 방지 | 영역 경계·무기 잘림·다른 상태 혼입 검사 |

개선 순서는 판정/자원 일치 → 입력/정보 읽기 → 선택 가치 → 화려한 효과다. 현재 효과가 없어서 재미없는지, 판단 자체가 없어서 재미없는지를 구분한다. 약점을 해결하지 못한 채 콘텐츠 수를 늘리지 않는다.

## 07 · SWOT — 기회를 제품의 차이로 바꾸기

| 기회 | 실현 전략 | 실제 장면 | 성공 신호 | 중단·축소 조건 |
| --- | --- | --- | --- | --- |
| 서로 다른 퍼즐 숙련을 연결 | 보드는 자율 전환, 기본 기술은 CHAIN 없이 사용 가능 | 급하면 한 줄로 방어, 여유가 있으면 증폭 준비 | 두 보드 사용 이유가 서로 다름 | 모든 기술 전에 두 보드를 강제 방문 |
| 보스 읽기와 퍼즐 준비의 연결 | 현재와 다음 위협을 숨기지 않음 | 약한 타격엔 기본 방어, 다음 강타에 증폭 보존 | 미래 위협이 지출을 실제로 바꿈 | 다음 정보가 장식으로만 남음 |
| 적은 기술로 깊은 선택 | HP·보스 HP·MP·증폭·준비 상태를 바꾼 사례 설계 | 방어해야 살던 상황이 처치 가능한 HP에서는 공격으로 역전 | 다양한 상황에서 선택 이유가 달라짐 | 한 기술이 모든 상황에서 지배 |
| 애니메이션 같은 명료한 시각 | 큰 얼굴·큰 보스·강한 문양·짧은 예비/타격 상태 | 보스 몸짓과 ETA, 실제 피해가 같은 사건을 가리킴 | 효과를 꺼도 판정 이해, 켜면 만족 상승 | 화면 흔들림 없으면 위협을 못 읽음 |

이 기회는 시장 규모나 매출 예측이 아니다. 경쟁작 기능의 혼합보다, 이 프로젝트에서 하나의 일관된 판단 경험으로 연결되는지가 기준이다. 첫 완결 세션에서 증거를 얻은 뒤에만 다른 직업과 긴 진행 구조를 확장한다.

## 08 · SWOT — 위험·완화·복구 계획

| 위험 / 조기 신호 | 예방 | 발생 시 조치 | 검증·책임 |
| --- | --- | --- | --- |
| 한 보드 최적 전략 / CHAIN 무시 승리만 반복 | 다양한 자원·보드 준비·위협 상태를 포함 | 해당 상황의 한계 이득을 비교, 경제를 좁게 조정 | 설계 담당; 승패만 아니라 선택 이유 기록 |
| 의무 순환 / 플레이어가 세금처럼 설명 | 강제 전환·추가 비용·전용 쿨다운 배제 | 증폭 효용·필요 빈도 축소 후 재검사 | UX/밸런스; 개인 선호를 결함으로 단정 금지 |
| 이미지 퇴행 / 보스 칸에 플레이어 노출 | ID→파일 해시→영역→노드 한 경로 | 해당 바인딩 되돌리고 기존 버전 유지 | 자산/통합; 전체 시트와 단일 칸 구분 |
| 일정 확대 / 기술·직업·효과 수 증가 | 세 기술·한 보스·완결 세션의 범위 잠금 | 가장 약한 가설부터 줄이고 확장 보류 | 제작; 기능 수가 아니라 검수 통과로 계산 |
| 상용 유사성·권리 문제 | 경쟁작 캐릭터·로고·화면 자산 복사 금지 | 문제 자산 격리·대체, 출시 판단 보류 | 출시 권리 별도 검토; 지금 법률 PASS 없음 |
| 기획과 실행 정본이 혼합 | R1/비교실험/기존 실행을 명시 | 실제 코드 기준으로 상태를 내리고 문서 교정 | 정본 담당; 미실행을 PASS로 승격 금지 |

복구는 한 기능·한 자산 단위로 가능하게 한다. 기존 실행 버전과 PDF·승인 원본은 보존하고, 새 이미지가 확정되어도 한꺼번에 오래된 파일을 삭제하지 않는다. 소비 참조가 0이고 복원이 가능한 자료만 별도 정리한다.

## 09 · SWOT 교차 전략 — 행동으로 닫기

| 전략 | 묶는 근거 | 실행 항목 | 우선순위 / 완료 조건 |
| --- | --- | --- | --- |
| SO: 강점으로 기회 확대 | 보존 보드 + 현재/다음 예고 | 준비를 남겼다가 돌아오는 교육과 위기 사례 | P1 / 복귀 배열 동일, 다른 대응 이유를 설명 |
| WO: 기회로 약점 개선 | 안정된 세 기술 + 복잡한 자원 용어 | 저장 증폭과 연쇄 깊이 분리, 효과·실제 회복·비용 동시 표기 | P1 / 오해한 프리뷰 결과 0, 이해 여부 사람 검사 |

P0는 데이터·판정·복구 오류, P1은 핵심 경험·가독성, P2는 표현 강화다. 재미와 접근성의 관찰 결과에 따라 순서를 재평가한다. 동일 문제가 반복되면 새 문서나 도구부터 만들지 않고 해당 책임 코드·생성기·검증에 재현 사례를 추가한다.

## 13 · 메인 — 무엇을 시작하는지 명확하게

@screen main

처음 보는 버튼은 시작·연습·설정·종료다. 첫 시작은 전투 안내로 이동하며, 다음 실행에서도 자동으로 전투를 시작하지 않는다. 첫 완결 세션에서는 영구 성장·장비·재화 상점을 노출하지 않는다. 아직 없는 콘텐츠를 잠긴 아이콘으로 채우지 않는다.

| 조작 | 결과 | 예외·복귀 |
| --- | --- | --- |
| 시작 | 안내 → 출격 확정 후에만 새 전투 생성 | 안내 취소는 자원·전적 변화 없이 메인 |
| 연습 | 단계 선택 후 무기록 연습 | 종료 즉시 메인, 일반 승리로 집계 금지 |
| 설정 | 입력·음량·효과·UI 크기 | 적용/취소 구분; 현재 설정으로 복구 가능 |
| 종료 | 종료 확인 | 취소하면 포커스를 종료 버튼에 복원 |

배경은 새 요새 이미지, 제목·메뉴·버전 표시는 별도 텍스트다. 임시 제목을 이미지 안에 굳혀 넣지 않아 이름 변경이 전체 배경 재제작으로 이어지지 않게 한다.

## 14 · 전투 안내 — 약속하고 출격한다

@screen briefing

현재 보스, 난도, LINE/CHAIN의 역할, 기본 자원, 실패 규칙과 조작을 먼저 보여 준다. “시간이 흐르는 중”처럼 보이는 가짜 카운트다운은 없다. 출격 전에는 전투가 아직 시작되지 않았다.

| 표시 | 내용 | 출격 시 계약 |
| --- | --- | --- |
| 목표 | 균열 파괴자를 쓰러뜨려 첫 전투를 끝낸다 | 보스 HP0에서 승리 |

보스 HP와 수치는 아래 R1 세션 상세를 따른다. 안내 중 변경한 난도는 출격 확정 시 고정한다. 전투 중 숨은 난도 상승이나 실패에 따른 몰래 완화는 없다.

## 15 · 전투 구성 — 조작과 위협을 같은 무게로

## 17 · CHAIN 화면 — 한눈에 읽히는 교환과 연쇄

@screen chain

8×8 보드를 왼쪽 중앙에 크게 배치한다. 한 칸 선택 → 상하좌우 이웃 선택으로 교환한다. 같은 칸 재선택·취소는 비용이 없다. 키보드는 방향키로 커서, Enter로 선택/교환, Esc로 선택 취소를 우선 처리한다. 마우스와 키보드는 같은 공개 입력 함수를 사용한다.

선택은 색 변화만이 아니라 이중 테두리·커서로 표시한다. 맞지 않은 교환은 원래 위치로 돌아가며 “일치 없음 · 증폭 −1”을 실제 감소량으로 보여 준다. 증폭0이면 “증폭 감소 없음”이다. 단순 범위 밖 클릭은 실패 교환으로 세지 않는다.

해결 중에는 입력 잠금과 현재 연쇄 깊이를 표시한다. 저장 증폭은 우측 HUD에 남아 있고, “연쇄2”와 “증폭 보유6”을 서로 다른 위치·문장으로 읽는다. 대각선은 이 R1 권장안에서 일치하지 않는다.

## 18 · 스킬 오버레이 — 읽고 확정한다

@screen skill

공격 / 방어 / 회복을 선택하고, 같은 기술의 기본·증폭을 비교한다. 현재 보유 증폭이 기술 이름이나 효과 종류를 바꾸지 않는다. T1~T6와 기존 C1~C10을 새 선택 행으로 복원하지 않는다.

상세 카드의 순서: 큰 아이콘과 이름 → 한 문장 목적 → 대상/실제 효과 → MP·증폭 비용 → 사용 후 잔량 → 불가 이유 → 사용/취소. “전술 일시정지” 표시는 공유 ETA 가까이에 둔다.

확정 전에는 지출이 없다. 사용 버튼은 클릭과 키보드 반복 입력을 묶어 한 번 처리하고 최신 상태를 다시 검사한다. 자원·대상이 변했으면 새 프리뷰를 보여 주며 임의로 다른 기술을 사용하지 않는다. 취소와 읽기만으로 보드가 바뀌지 않는다.

## 19 · 공유 행동 타이머 — 한 시간을 두 의미로 읽기

@screen timer

타이머는 현재 보스 행동까지 남은 시간이며, 동시에 플레이어가 대응할 수 있는 시간이다. 별도의 플레이어 턴 제한·행동 횟수·28초 고정 예산은 없다. 화면의 원형/막대 진행과 ETA 숫자는 같은 값에서 나온다.

| 상태 | 표시 | 실제 처리 |
| --- | --- | --- |
| 피해 행동 진행 | “다음 타격까지 8.4초” | 현재 행동 남은 시간 감소 |
| 비피해 안정 진행 | “안정 종료까지 8.0초 · 피해 없음” | 같은 ETA, 다음 행동 전 자원 준비 구간 |
| 임박 | 2.0초 이하 아이콘+문구 강조 | 피해량을 몰래 높이지 않음 |
| 전술/수동/포커스 정지 | 정지 이유, 고정 숫자 | 퍼즐·보스·지속 상태·연출 시간 모두 정지 |
| 타격 확정 | “타격 처리 중” | 이미 확정한 사건을 뒤늦게 취소 불가 |
| 다음 예고 | 다음 행동의 준비 시간 | 현재 시점에서의 절대 도착 시각으로 오해시키지 않음 |

표시 반올림 때문에0.0인데 아직 미확정이면 “곧 발동”으로 표시한다. 실제 사건 판정은 표시 문자열이 아니라 시뮬레이션 값과 commit 상태로 결정한다.

첫 보스는 거대한 현무암 갑주와 보랏빛 균열핵, 긴 망치로 읽는다. 갑주 재질은 날카롭고 큰 덩어리로 정리하며, 플레이어 얼굴과 다른 실루엣을 유지한다. 보스의 이름·HP·현재 행동은 그림에 구워 넣지 않는다.

## 33 · 연습 — 세 번의 작은 이해

| 단계 | 준비 상태 | 해야 할 행동 | 통과/복귀 |
| --- | --- | --- | --- |
|1 LINE→MP | 마지막 한 줄에 맞는 조각이 있는 고정 교육 보드 | 한 줄 지우기 → MP+10 확인 | 플레이어가 MP 위치를 확인 후 다음 |
|2 CHAIN→증폭 | 한 교환으로 일치하는 검증된 보드 | 파동 해결 → 저장 증폭 증가 확인 | 연쇄 깊이와 보유량의 차이 설명 |
|3 위협→스킬 |35강타 예고, MP10·증폭2, HP10 | 스킬 열기 → 정지 확인 → 증폭 방어 |5HP 생존과 비용을 보고 종료 |

교육은 무기록 별도 세션이다. 단계1·2의 보스 시간은 멈춰 있으며 이를 명시한다.3단계는 연습 시작을 누른 뒤14초 예고를 실행한다. 실패하면 해당 단계 초기 상태로 복귀하고 일반 전적에 포함하지 않는다. 건너뛰기는 가능하고 설정/도움말에서 다시 볼 수 있다.

교육 보드의 실제 배열과 목표 교환·착지는 blueprint-data.json에 준비한다. LINE은 맨 아래6칸만 채운 행에 가로 I조각을 놓는 상황, CHAIN은 (2,0)과 (2,1)을 바꾸면 맨 위 R3개가 일치하는 상황이다. 구현 첫 단계에서 실제 R1 매처와 다시 대조한다. 교육 완료 저장은 마지막 결과 확인 후이며 버튼 클릭만으로 이해를 PASS로 판정하지 않는다.

## 35 · 저장·오류·실패 복구 계약

첫 세션은 설정·연습 완료·최근 결과 요약만 저장한다. 전투 중간 이어하기는 포함하지 않고 메인에서 제공하지 않는다. 창을 닫으면 진행 중 전투는 이어지지 않는다는 문구를 종료 확인에 표시한다. 향후 캠페인 저장으로 오해될 빈 이어하기 버튼을 만들지 않는다.

| 데이터 | 스키마 / 저장 시점 | 실패 처리 |
| --- | --- | --- |
| 설정 |settings_version1, 음량0~1·입력맵·효과 축소·UI 배율 | 잘못된 항목만 기본값 복원, 사용자에게 알림 |
| 연습 |tutorial_version1, 완료 단계0~3 | 단계 완료 결과 확인 후 한 번 기록 |
| 결과 |result_version1, run_id·mode·seed·종료·누적 통계 | 임시 파일 기록 검증 후 교체, 중복 run_id 지급 없음 |

저장 파일은 user:// 아래 프로젝트 전용 경로를 사용한다. 임시 파일과 마지막 정상 백업을 분리하고 잘못된 JSON을 새 게임 데이터로 조용히 덮어쓰지 않는다. 호환되지 않는 높은 version은 보존하고 읽기 불가를 알린다. 외부 계정·클라우드·개인정보 수집은 없다.

전투 도중 데이터 오류는 승리/패배와 구분한 복구 오류 화면으로 정지한다. 다시 시도는 전투 처음부터이며 잘못된 거래의 일부 지출만 남기지 않는다. 실제 쓰기·손상·복구 테스트는 구현 이후 검수 항목이다.

| 전투 종료 /100 | 보스 패배 또는 플레이어 패배 고정 | 낮은 표현 모두 종료 | 승패 한 번 |
| 피해 행동 commit /80 | 타격120ms → 회복240ms | 종료 외에는 타격 의미 유지 | 피해는 commit 결과, 프레임으로 재발생 금지 |
| 비피해 안정 /0 | recover_pose 진입부터 회복 자세8초 유지 | ETA 종료 시 다음 행동의 상태로 전이 | commit에 타격 컷·충격음·피격 표시 없음 |
| 준비 /60 | 약타 마지막0.6초, 강타 마지막1.2초 준비 컷 | ETA가 변하면 같은 행동 기준 재계산 | 몸짓이 별도 타이머 아님 |
| 보스 피격 /40 | 피격100ms | 준비/타격 중엔 컷 대신 HP·짧은 강조 | 보스 경직·지연 없음 |
| 평상시 /0 | 대기 | 위 사건으로 전이 | 전투 시간에 영향 없음 |

일시정지는 위 상태의 남은 시간을 동결한다. 화면 포커스가 돌아왔을 때 밀린 타격을 한꺼번에 재생하지 않는다. 여러 스킬 결과는 각 거래 ID로 수치 반영하고 낮은 우선순위 장식만 합칠 수 있다. 결과 로그는 합치지 않는다.

프레임이 없거나 효과 축소가 켜져도 현재 예고·ETA·피해·방어·회복 텍스트는 정확히 보인다. Aseprite의1프레임 원본은 정적 아틀라스 편집용이며 이 재생 시간이 저장된 완성 동작 파일이 아니다. 구현 담당자가 위 시간을 사용해 이벤트 프리젠터를 연결한다.

안정 구간의8초는 표준 준비 시간 전체이며 여유 모드에서는10초다. 그동안 공격을 받아 피격 표현을 보였다면 남아 있는 안정 자세로 복귀한다. 이는 보스 HP 회복·Ward 소비·추가 시간 보상이 아니다. 장면의 “회복 자세”와 기술 “플레이어 HP 회복”을 구별한다.

## 43 · 데이터 표 — 한 사실의 책임 원본 하나

| 데이터 | 필수 필드·허용 값 | 소비 책임 | 잘못된 입력 |
| --- | --- | --- | --- |
| 세션 설정 |rule_pack=R1, mode=standard/relaxed, player_hp100, boss_hp180, seed | 별도 R1 시작 구성 | 다른 rule_pack을 조용히 섞지 않음 |
| 기술 |id=strike/ward/recover, category, base/amp cost/effect | 스킬 정책·프리뷰·거래 | 음수·소수 비용·누락ID 거절 |
| 보스 행동 |action_id, instance_id, windup>0, damage≥0, kind | 스케줄러·예고·Ward | 중복 instance_id·알 수 없는 kind 거절 |
| 전투 상태 |HP, MP, charge, active_board, pause_reasons, terminal | 전투 세션 | UI가 직접 수정하지 않음 |

새 수치의 제작용 입력은 blueprint-data.json에 있으며 이 표는 그 의미를 설명한다. R1의 공통 보상·비용은 기존 원본을 참조하며 미래 runtime에 옮길 때 하나의 설정 경로로 통합한다. Markdown·JSON·코드에 서로 다른 밸런스를 독립적으로 유지하지 않는다.

## 44 · 실행 경계와 같은 프레임의 순서

@flow 명령 검증|정지·종료 재검사|활성 보드 진행|보상 반영|보스 진행·확정|결과·다음 예고

| 책임 | 재사용 / 변경 | 연결·불변조건 |
| --- | --- | --- |
| R1 bootstrap | 새 격리 구성, 기존 시작 함수 복사 금지 | 기존 함수가 시작한 스케줄러를 나중에 교체하지 않음 |

매 유효 명령과 피해 거래 직후 정지·종료를 재검사한다. 뒤 단계에서 얻을 보상을 앞 명령이 미리 쓰지 못한다. 현재 스킬 열기보다 먼저 보스가 commit됐다면 소급 취소하지 않는다. 같은 프레임 동시 처치가 가능한 미래 기능은 패배 우선 규칙을 명시하되 첫 직접 기술 세션에서 임의로 동시 피해를 만들지 않는다.

## 47 · 재미·독창성 검토 — 결과가 반대면 바꾼다

| 가설 | 관찰 | 반증 시 조치 |
| --- | --- | --- |
| 두 보드의 역할을 이해 | 첫 사용 전 목적·비용 예측, 도움 여부 기록 | 용어/프리뷰 먼저 수정, 규모 확대 보류 |
| 전환이 자발적 계획 | 전환 시점·당시 보드·자원·위협·이유 | 단순 상한 관리/필수 통행이면 경제 재검토 |
| 증폭 보존이 의미 있음 | 기본을 골랐을 때 미래 이득, 증폭 즉시 사용 이유 | 언제나 한쪽이면 UI 선택 축소 또는 효용 조정 |
| 실패해도 다시 해보고 싶음 | 패배 이유 설명·재도전 동기 | 복구/난도/설명 중 원인을 나눠 수정 |

Foundation §10의 A/B는 동일 초기 보드와 기존 시각으로 통제한다. 이번 새 그림·R1 문법·패널·난도를 그 실험에 몰래 넣지 않는다. 이후 R1에서 문법·실패 비용·표현을 한 번에 바꾸고 어느 하나 덕분이라고 결론 내리지 않는다.

첫 노출3명, 두 순서2/1 교차는 방향성 관찰일 뿐 통계적 증명이 아니다. 세 명 모두 역할을 무코칭으로 설명하고 최소 두 명이 두 보드 사용에 서로 다른 유용한 이유를 제시하는지 본다. 개인이 CHAIN을 적게 쓴 사실 하나로 실패 처리하지 않는다. 치명적 오표시·중복 효과·상태 손상은 평균으로 상쇄하지 않는다.

전체 구현 완료는 이번 승인 범위의 화면·시스템·데이터·이미지 소비가 모두 연결되고 자동/실행 검수가 통과했을 때만 말한다. 최종 재미·출시·권리 승인은 따로 남긴다.

## 50 · 무엇을 승인하고 무엇을 남기는가

| 구분 | 이번 검토 대상 | 승인 이후에도 남는 확인 |
| --- | --- | --- |
| 유지 | 자율 보드 전환·한 ETA·전술 정지·명시적 확정 | 실제 입력·타이밍 회귀 |

| 추가 | 첫 완결 세션·화면 아틀라스·새 상태 자산·복구·복기 | 실제 코드·화면·저장 연결 |
| 보류 | 추가 직업·장편 진행·영구 성장·연속 중간 프레임·출시 | 별도 경험/제작 근거와 승인 |
| 보호 | 기존 실행 버전·승인 자산·이전 PDF·열린 Draft | 참조0/복구 확인 전 삭제 금지 |

최종 확인할 핵심은 두 보드의 역할, 세 기술의 선택 방식, 큰 보스/읽히는 얼굴의 화면 구성, 새 그림의 방향이다. 세부 시간과 수치는 명시된 초기 권장값이며 실제 검수 결과에 맞춰 조정하되, 코어 의미를 바꾸는 변경은 다시 설명한다.

문서 수정은 절 번호·원하는 변화·이유를 알려 주면 해당 책임 원본에 먼저 반영하고 PDF를 재발행한다. 이 PDF 자체를 독립 정본으로 고쳐 코드와 다른 규칙을 만들지 않는다.
