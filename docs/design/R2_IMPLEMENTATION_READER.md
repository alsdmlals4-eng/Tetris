# R2 게임 전체 구현 보완본

## 01 현재 게임과 이 책의 읽는 순서

LINE으로 자원을 준비하고 CHAIN의 파동마다 선택한 기술을 자동 발동하는 퍼즐 전투입니다. 현재는 외곽 전투, 중간 경로 선택, 균열 핵 전투로 이어지는 유한 원정이 실행됩니다. 세 전투는 연결된 캠페인의 첫 구현이며 전체 콘텐츠·재미·최종 아트가 완성됐다는 뜻은 아닙니다.

이 보완본은 실제 구현 상태를 먼저 보여 줍니다. 뒤에 붙인 기존 상세 블루프린트는 수정하지 않은 설계 검토 기록입니다. 그 기록의 '구현 전', '실행하지 않음' 문구는 당시 상태이며 현재 상태는 앞쪽 검증표를 따릅니다. 반대로 실행됐다는 사실이 최종 이미지·재미·출시 승인을 대신하지 않습니다.

@image docs/validation/r2-expedition-20260913/main-125.png

실제 Godot 메인 화면 캡처. 제목은 작업 표기이며 뱅가드는 직업명입니다. 기존 최종 브랜드를 임의로 확정하지 않았습니다.

## 02 시작부터 결말까지 연결

메인 → 원정 시작 → 외곽 출격 → LINE/CHAIN 전투 → 정비 하나 선택 → 주조소 또는 감시탑 → 전투/정비 → 균열 핵 → 승리 결말. 패배하면 해당 전투의 시작 상태로 재도전할 수 있습니다. 경로와 정비 선택은 재접속으로 바뀌지 않습니다.

@image docs/validation/r2-content-20260913/fork-125.png

실제 분기 화면입니다. 적 이름, 초기 체력, 첫 위협과 전체 행동 주기를 읽고 선택합니다. 키보드 포커스도 선택 중인 경로 예고를 갱신합니다. 설명은 실제 전투 owner가 계산한 시간과 피해를 사용합니다.

## 03 두 퍼즐과 네 자원의 역할

@resources

공격 준비는 다음 성공한 공격 스킬에 한 번 소비됩니다. 치유는 최대 체력에서 넘치지 않습니다. 시계 자원은 현재 확정 전 행동에만 적용되고 상한 초과분을 다음 행동으로 넘기지 않습니다. CHAIN 타일에는 직접 자원 보상을 다시 주지 않습니다. 같은 색 네 종류는 읽기 일관성을 위한 표현이며 두 보드의 경제 역할은 다릅니다.

@image docs/validation/r2-readability-20260913/chain-125.png

실제 CHAIN 화면. 보드는 한 번에 하나만 표시하며 좌우 전투 영역의 동일 폭을 유지합니다. 스킬 효과·최근 적용 결과와 적 예고는 퍼즐 조작과 함께 읽을 수 있습니다.

## 04 콤보 자동 스킬과 현재 위협

@skills

T1~T6는 수동으로 비용을 내고 사용하는 버튼이 아니라 이번 연쇄의 단계/효과를 읽는 용도입니다. ATK·DEF·SUP 계열을 선택하며 연쇄 중 계열은 고정됩니다. 한 파동에 여러 매치가 나도 자동 발동은 한 번, 다음 파동은 다음 단계입니다. 안정된 보드가 되면 단계는 초기화됩니다.

DEF는 현재 확정 전 적 행동의 방벽 목표값 중 큰 값을 사용합니다. 이미 끝났거나 확정된 행동에 뒤늦게 방벽을 옮기지 않습니다. 공유 타이머는 플레이어와 적이 서로 다른 시계를 쓰는 방식이 아니라 현재 적 행동까지 남은 시간입니다. 설명·설정·일시정지 중에는 게임 시간이 흐르지 않습니다.

## 05 현재 적 데이터와 전술 차이

@encounters

표는 표준 모드의 현재 카탈로그 수치입니다. 여유 모드는 전투 owner의 준비시간 배율을 사용합니다. 외곽은 학습, 주조소는 느린 강타 대응, 감시탑은 짧은 연속 위협, 핵은 마무리 역할입니다. 숫자 차이와 텍스트는 구현됐지만 모든 적이 독자적인 최종 그림·모션을 갖춘 것은 아닙니다.

## 06 정비, 저장, 실패와 회복

@supplies

정비는 전투 사이에 한 번만 적용합니다. 다음 전투에서는 퍼즐, 공격 준비, 방어도, 행동별 방벽을 초기화하고 선택한 정비의 시작 보너스를 적용합니다. 체력은 이어집니다. 따라서 미완성 퍼즐을 다음 적에게 가져가거나 보상을 중복 수령하지 않습니다.

@image docs/validation/r2-content-20260913/supply-125.png

일반 단일 전투와 원정은 서로 다른 저장 파일을 사용합니다. 원정 카탈로그 식별, 전투 설정, seed, 현재 진행을 함께 검증합니다. 손상된 부분 저장을 억지로 읽지 않고 검증된 백업을 시도합니다. 복원은 전체 정지 상태입니다. 체크섬은 보안·부정행위 방지나 모든 전원 장애의 원자성 보장이 아닙니다.

## 07 실제 이미지와 아틀라스 소비 관계

@assets

아틀라스는 아래와 같이 실제 파일·해시·영역을 가진 자산입니다. '게임에서 표시됨', '편집 가능한 원본 보유', '최종 그림 승인', '프레임 애니메이션 완성'은 각각 다른 상태입니다. 기존 자세 선택과 간단한 움직임은 구현됐지만 매끈한 중간 프레임 애니메이션을 자동으로 의미하지 않습니다.

감시탑 새 시안은 첫 버전에서 자세 영역 침범, 수정본에서 RGB 체크무늬가 확인되어 게임에 넣지 않았습니다. 원본 보존 후 재제작 대상으로 남겼으며 기존 게임 이미지를 불합격 파일로 바꾸지 않았습니다.

## 08 음향, 설정과 접근성 경계

@image docs/validation/r2-audio-20260913/options-error-125.png

실제 옵션 화면이며 오류 문구는 배치 검사용으로 넣은 예시입니다. 효과음과 짧은 승리 징글은 독립 음량을 사용합니다. 0은 재생 차단, 취소는 이전 음량 복원입니다. 네 개의 효과음 재생 슬롯과 징글 한 개를 재사용하므로 연쇄마다 재생 노드가 늘어나지 않습니다. 휴식에는 적 타격음을 내지 않습니다.

Kenney의 CC0 음원 중 소비하는 여섯 파일만 포함했습니다. 엔진 재생·음량·음소거와 패키지 포함은 검증했습니다. 스피커 청취, 음량 균형, 청각 접근성, 전체 배경음악은 완료하지 않았습니다. 무음에서도 위협과 효과를 읽을 수 있도록 시각 정보를 유지합니다.

## 09 SWOT와 개선 우선순위

| 구분 / 현재 상태 | 강화·보완 조치 | 요청 이유 / 기대효과 | 확인 방법·재검토 조건 |
|---|---|---|---|
| 강점: 준비와 발동을 나눈 두 퍼즐 | LINE 보상 내역과 CHAIN 최근 발동을 계속 보여 준다 | 행동과 결과의 인과를 학습하고 계획한 공격의 만족을 만든다 | 첫 노출 플레이어가 자원→발동을 설명하는지 확인 |
| 강점: 읽을 수 있는 적 예고 | 분기 선택 전에도 실제 행동 주기를 제공 | 반사신경만이 아닌 준비와 대응 선택을 강화 | 예고를 이용한 DEF·SUP 선택 및 피해 변화 관찰 |
| 약점: CHAIN만 빠르게 반복하면 쉬울 수 있음 | 생각 시간 포함 실험과 실제 플레이를 분리해 수집 | 무지연 테스트 봇 승리는 재미·난도 증거가 아님 | 인간 입력 지연, 보드 전환, 죽음 원인, 선택 편중 분석 후 수치 조정 |
| 약점: 적 그림과 패턴 정체성의 불일치 | 실제 프로필별 실루엣과 여섯 자세를 검증 후 연결 | 같은 망치 보스가 활 위협을 쓰는 혼동을 줄임 | 실제 알파·영역·피벗과 적 인지 테스트 |
| 기회: 짧은 분기 원정 | 정비 선택의 실효값과 경로 위협 비교를 명확히 유지 | 새 화폐나 파밍 없이 재도전 이유를 제공 | 정비/경로 선택률이 한쪽으로 고정되면 원인 조사 |
| 기회: 여유 모드와 읽기 정지 | 난도 변경을 명시하고 전체 정지 경계를 회귀검사 | 학습 부담을 줄이면서 숨은 난도 조절을 피함 | 입력 장치·글꼴·설명 중 상태 불변 검증 |
| 위협: 화면·규칙의 버전 퇴행 | 실제 consumer와 정확한 소스 버전에 PDF를 결합 | 예전 시안을 현재 실행으로 오해하지 않게 함 | 자산 해시·export·native 캡처·main readback |
| 위협: 끝없는 기능 추가와 자산 용량 | 현재 유한 캠페인을 우선하고 온라인/상점/추가 직업 보류 | 완성 경계를 지키고 유지보수·권리 검수 범위를 제어 | 새 기능은 기존 재미 문제를 해결하는 근거 필요 |

## 10 벤치마킹을 흡수한 방식

| 자료 | 관찰 / 차이 | 판단 |
|---|---|---|

벤치마크는 현재 게임 의미의 정본이 아닙니다. 본 프로젝트의 독창성 가설은 서로 다른 퍼즐의 역할 분리와 같은 적 타이머에 대한 준비·자동 발동의 연결입니다. 독창성을 법적 독점이나 플레이어 재미 검증으로 과장하지 않습니다.

## 11 실행 증거와 남은 완료 조건

@verification

@image docs/validation/r2-content-20260913/ending-125.png

실제 원정 결말 화면. 자동 명령 드라이버는 자원이나 체력을 주입하지 않고 정상 교환 명령으로 완주했지만 생각 시간이 없으므로 난도·재미 판정에는 쓰지 않습니다. 남은 필수 작업은 적별 최종 이미지/모션, 전체 음향 품질, 지원 화면·입력·실패 흐름의 최종 통합 검사, 플레이어 검증입니다. 세 전투와 자동 테스트만으로 게임 전체 완성이라고 쓰지 않습니다.

## 12 보존한 상세 설계 검토 기록 안내

다음 페이지부터는 기존 통합 블루프린트 원문입니다. 상세 규칙, 시스템 설명, 초기 데이터 표, 아틀라스, 모션 명세, 이전 SWOT와 수용 기준을 잃지 않도록 원본 페이지를 그대로 붙였습니다. 초기 단일 보스 범위와 과거 미실행 상태는 원정 확장/현재 검증 상태와 구분하십시오. 최신 구현 차이는 이 보완본과 저장소의 현재 책임 원본을 우선합니다.
