# R2 · 준비한 자원으로 연쇄를 전투로 바꾼다

## 01 · 이번 개정의 권한과 읽는 순서

2026-09-11 사용자 승인: 권장 B안. LINE에서 공격·방어·치유·시간 자원을 얻고, CHAIN에서는 매 소거 파동마다 선택 계열의 스킬이 자동 발동한다. CHAIN의 타일 직접 보상은 없다. 구현은 사용자가 보류했다.

이 문서와 autocast-r2-data.json은 새 기획의 변경된 전투 규칙을 소유한다. 기존 R1 문서·51쪽 PDF의 MP, 증폭, 수동 사용, 7색/6색 타일과 해당 수치·화면은 이 개정에 의해 대체된다. 기존 실행 버전은 수정하지 않는다. 기존 R1의 생산·검수 구조는 참고하되 승인된 새 게임처럼 취급하지 않는다.

상태: 방향 승인 / 상세 수치 권장 초안 / 새 타일 후보 / 보스 투명도 실패 / 구현·실행·플레이 검증 미실시. 이 개정 PDF는 변경 규칙 검토본이며 전체 최종 블루프린트 완성본이 아니다.

먼저 02~06의 전투 흐름, 다음 07~12의 예외와 화면, 마지막 13~20의 자산·SWOT·구현 인계를 읽는다. 이전 자료와 충돌하면 이 개정의 해당 항목이 우선한다.

핵심 차별화 가설: 같은 네 문양을 LINE에서는 자원 준비로, CHAIN에서는 선택 계열의 연속 전투 효과로 읽으며, 보이는 적 행동 시점에 맞춰 스스로 전환한다.

## 03 · 한 번의 플레이 흐름

메인 → 출격 안내 → LINE 또는 CHAIN 선택 → 적 현재 행동 관찰 → LINE 자원 획득 → 계열 선택 → CHAIN 성공 교환 → 소거 파동마다 자동 발동 → 안정화 → 다음 판단 → 승리/패배 → 결과·재도전.

전투는 하나의 연속 시간축이다. 보드 두 개가 동시에 보이지 않는다. 전환해도 비활성 보드의 배치·다음 조각·난수 상태는 보존한다. 보스 ETA는 일반 입력·전환·연쇄 연출 동안 흐른다. 메뉴 일시정지는 모두 함께 멈춘다.

전환 요청은 진행 중인 조각 확정/소거 트랜잭션 또는 CHAIN 전체 연쇄가 끝난 안전 경계에서 한 번 처리한다. 보스 피해로 HP가 0이 되면 대기 입력과 후속 파동을 취소한다. 연쇄가 위험 행동을 무적 상태로 회피하게 만들지 않는다.

자원 가산 수는 소거한 고유 셀의 집합으로 센다. 소거 선 수, 교차 매치의 중복 개수, VFX 입자 수가 아니다. 색상 외에 문양·명칭·수량을 함께 표시한다. CHAIN 화면에는 항상 '콤보 → 선택 스킬 자동 발동 / 타일 직접 보상 없음'을 표시한다.

## 05 · LINE 준비 규칙

10열×20가시행, 숨김 4행. 조각 형태는 기존 7종·7-bag·회전·HOLD·NEXT·고스트 입력 구조를 재사용 검토한다. 형태와 자원 종류를 분리한다. 네 색을 조각 형태 ID로 사용하지 않는다.

권장 생성안: 각 조각의 네 셀은 동일 자원 문양. 형태 bag과 별도로 공격·방어·치유·시간 각 1개로 구성된 자원 bag을 섞어 조각 생성 시 하나 배정한다. HOLD와 NEXT는 형태와 배정 문양 모두 보존·표시한다. 전환·홀드로 문양을 다시 뽑지 않는다. 매 조각 네 문양 하나씩 강제 혼합하는 안은 의도적인 자원 선택을 약화시켜 첫 검증에서 제외한다.

한 번에 여러 줄을 지우면 줄 수와 무관하게 실제 셀 개수만 보상한다. T-spin·연속 4줄·백투백은 우선 점수·연출 보상이며 자원 배수로 겹치지 않는다. 지워진 셀 ID와 line_clear_id로 재전송 시 중복 보상을 막는다.

권장 넘침: HP25 손실 후 LINE만 초기화. 방어도·방벽으로 이 실패 피해를 막지 않는다. 일반 보스 피해와 원인을 구분한다. HP가 남으면 계속하며, CHAIN 배치는 보존한다. 수치는 테스트 전 권장안이다.

## 06 · CHAIN 자동 발동과 계열 고정

8×8 보드, 네 문양. 인접 상하좌우 교환, 가로·세로 직선 3개 이상을 매칭한다. 대각선 소거는 이전 실행 버전의 특징이지만 R2 첫 검증에서는 제외한다. 색상 수 감소와 함께 과도한 자동 연쇄를 줄이는 권장안이며 실측 전이다.

성공 교환 전 ATK/DEF/SUP를 고른다. 성공 교환을 확정할 때 category_snapshot과 chain_id를 저장하고 연쇄 동안 계열 변경을 막는다. 잠금 사유와 해제 시점을 표시한다. 안정화 이후 바꿀 수 있다. 미리보기는 계열 예약을 바꾸지 않는다.

한 파동 = 현재 보드에서 동시에 성립한 모든 매치의 고유 셀 합집합. 콤보 +1 → 단계 결정 → 해당 계열 기술 1회 자동 적용 → 소거/낙하/보충 → 다음 파동. 두 그룹 동시 소거는 2회 발동이 아니다. 수동 USE·CONFIRM·MP 부족 하향 발동은 없다.

권장 콤보는 이번 한 연쇄의 깊이이며 보드가 안정되면 0으로 돌아간다. 과거 누적 Combo 재화를 이월하지 않는다. 화면의 최대 콤보 기록은 별도 통계다. 잘못된 교환은 원위치, 자원·스킬 효과 없음. 다음 연쇄는 다시 C1부터다.

## 07 · 단계와 스킬의 역할

T1~T6는 지금 도달한 단계/다음 발동 효과를 보여 주고 눌러 설명만 미리 볼 수 있다. 단계를 수동 선택하지 않는다. 권장 단계는 min(이번 연쇄 파동 번호, 6). C7 이후에도 T6 기술이 파동마다 발동하고 실제 콤보 숫자는 증가한다. 단계 제한과 콤보 표시를 혼동하지 않는다.

| 단계 | ATK · 균열 베기 피해 | DEF · 현재 행동 방벽 목표치 | SUP · 응급 회복 HP |
| --- | --- | --- | --- |
| T1 | 4 | 3 | 2 |
| T2 | 6 | 5 | 3 |
| T3 | 8 | 7 | 4 |
| T4 | 11 | 10 | 5 |
| T5 | 14 | 13 | 7 |
| T6 | 18 | 17 | 9 |

이 18개 수치는 별도 기술 이름 18개를 강제로 만드는 대신 세 가지 명확한 목적을 단계별로 강화하는 시험값이다. 계열 아이콘은 3개를 재사용하고 단계 테두리·숫자를 데이터로 표시한다. 새 아이콘 18장을 불필요하게 늘리지 않는다.

DEF는 max(현재 방벽, 단계 목표치)로 갱신하며 파동마다 더하지 않는다. 현재 미확정 행동 instance에만 묶이고 그 행동이 끝나면 사라진다. SUP는 최대 HP까지 즉시 회복. 초과 회복을 공격/방어/시간으로 자동 전환하지 않는다. ATK만 공격 가산치를 소비한다.

## 08 · 공격 가산치와 피해 예외

LINE에서 얻은 공격 가산치를 bank라 부른다. ATK 성공 시 총 피해 = 단계 기본 위력 + bank. 실제 공격 트랜잭션을 확정한 뒤 bank를 0으로 만든다. DEF/SUP, 설명 열기, 잘못된 교환은 bank를 소비하지 않는다. 기본안에는 공격 bank 상한을 추가하지 않는다.

예: 검 타일7개 → bank7. 다음 연쇄 ATK T1=4+7=11, T2=6, T3=8. 총25. 은행7을 매 파동 더하지 않는다. 적이 이미 죽었거나 공격 적용 전에 대상이 무효화되면 bank를 소비하지 않고 전투 종료 처리를 우선한다.

첫 콘텐츠에는 다단히트·반사·회피·무적을 넣지 않는다. 향후 다단히트는 bank를 첫 유효 피해 타격에 한 번만 적용하고, 전체 스킬 실행 ID로 중복 소비를 막는다. 시각 효과나 애니메이션 콜백이 추가 피해를 발생시키면 실패다.

## 09 · 방어·회복·시간 상세

일반 보스 피해 D에서 현재 행동 방벽 W를 먼저 쓰고, 남은 피해에서 누적 방어도 A를 소모한 뒤 HP에 적용한다. 사용한 방벽/방어도만 차감. 행동이 종료되면 남은 W는 소멸, A는 다음 행동으로 보존한다. 방어도는 고정 비율 감소가 아닌 피해 흡수량이다.

예: 보스 피해35, W7, A10 → HP 피해18, W0, A0. 같은 연쇄에서 DEF T1·T2·T3가 발동해도 W=3+5+7이 아니라 최대7이다. 지속적 준비 자원과 순간 대응 기술을 구분하기 위한 선택이다.

시간은 현재 미확정 action_instance_id에 한해 min(시계 수×0.25초, 3초−이미 연장한 양)을 더한다. 현재 행동마다 +3초 한도, 새 행동에서 초기화. 기존 scheduler의 commit boundary 이후에는 0초, 남는 시계 효과는 '확정/한도 때문에 미적용'으로 표시하고 다음 행동에 이월하지 않는다. 0.25와 3은 조정 가능 시험값이다.

## 10 · 같은 순간 발생하는 사건의 순서

권장 고정 시뮬레이션 tick마다: 메뉴 pause → 보스 확정 경계 도달 처리 → 이미 확정된 보스 피해 → HP 종료 판정 → 새 LINE/CHAIN 소거 트랜잭션 → 자원/자동 스킬 → 적 HP 종료 판정 → 낙하·보충·다음 행동 예약 → 화면 갱신.

따라서 같은 tick에서 치명적 보스 피해가 확정되면 뒤의 자동 회복이 플레이어를 부활시키지 않는다. 경계 직전 아직 미확정인 행동에는 정상적으로 시간 타일이 적용된다. UI에 표시한 ETA를 보고 소급 취소하는 별도 경로를 만들지 않는다. 실제 timing 설정의 commit_lead를 구현 시 검증하고, 임의 0초로 대체하지 않는다.

DEF가 발동했지만 해당 행동이 이미 확정됐거나 피해 없는 안정 행동이면 방벽을 만들지 않고 '보호 대상 없음'을 기록한다. 효과가 없는 발동은 타 계열로 바꾸거나 다음 행동에 몰래 예약하지 않는다. 연쇄 시작 전 이 가능성을 예고한다.

## 11 · 50:50 화면 계약

1280×720 기준 바깥16, 중앙 간격16, 좌우616×688. 왼쪽은 한 보드와 하단 안내. 오른쪽은 보스+HP300, 현재/공유 타이머/다음116, 얼굴·자원96, 계열·단계·자동 발동 설명140, 구간 간격합36. 합계688.

보스는 환경과 분리한 투명 캐릭터를 보스 영역에 크게 배치한다. 플레이어 얼굴 최소96×96. 화면을 채우려고 캐릭터 비율을 찌그러뜨리지 않는다. 보스 HP/이름이 실루엣을 가리지 않도록 상단 별도 공간 확보. 얼굴과 보스를 잘못 연결하지 않도록 asset role을 검증한다.

타이머 구간은 현재176 / 중앙타이머192 / 다음176 / 내부 여백·간격72=616. 중앙에는 현재 행동의 남은 시간과 추가시간 사용량, 양옆에는 패턴 이름·직접 피해·상태 영향. 다음 패턴은 순서 예고이며 별도 확정 ETA인 것처럼 보여 주지 않는다.

스킬 구간은 ATK/DEF/SUP → T1~T6 읽기/미리보기 → '다음 파동: 균열 베기 T2 / 기본6 / 가산0' → '최근: T1 / 피해11'. 연쇄 중 계열 잠금, 수동 사용 버튼 없음. 상세보기는 전체 일시정지에서 읽되 선택 계열 스냅샷을 바꾸지 않는다.

## 12 · 튜토리얼과 실패 복구

1단계 LINE: 고정 학습 배치에서 검4·방패2·하트2·시계2의 한 줄을 지워 결과 +4/+2/+2/+0.5초를 확인. 학습 정지 중에는 ETA 수치만 설명하고 일반 전투 승리 기록에 넣지 않는다.

2단계 CHAIN: 계열 ATK, 두 그룹 동시 소거 fixture에서 C1 기술이 단 한 번 발생함을 확인. 후속 보충 매치로 C2 발동. 결과 카드에 '타일 보상 0 / 자동 기술 2회'를 표시한다. 검 bank는 C1에만 적용.

3단계 적 큰 공격 전에 LINE으로 방어/시간 준비 → DEF CHAIN. 4단계 메뉴 pause/resume 후 시간·계열·보드가 보존됨을 확인. 매 단계 실패는 그 학습 단계만 다시 시작하며 일반 난수/수치를 몰래 보정하지 않는다.

CHAIN 초기 배치는 즉시 매치 없이 유효 교환이 최소 하나 있어야 한다. 안정화 후 가능한 교환이 없으면 매칭·보상 없이 재배열. 검증된 구성 fallback을 사용하고 무제한 탐색 금지. 과도한 자동 연쇄는 최대64파동에서 보상 없는 안정 배치 복구와 진단 로그를 남기는 안전 상한을 권장한다.

## 13 · 이미지 아틀라스와 승인 상태

@tiles

새 타일 PNG 1254×1254, 2×2, 셀627×627. 순서 공격(0,0), 방어(627,0), 치유(0,627), 시간(627,627). 이 숫자는 좌상단 좌표이며 region 크기는 모두627. 불투명한 사각 타일은 의도된 형식이다. 게임에서는 양 보드가 이 동일 atlas를 참조한다.

Aseprite는 원본 보존·편집 가능한 .aseprite 저장·내보내기 검증에 선택했다. 한 프레임 static atlas이며 완성된 프레임 애니메이션이라고 부르지 않는다. PNG와 Aseprite 재출력의 RGBA 픽셀 일치를 실제 확인했다. 현재 후보, 사용자 최종 이미지 승인과 runtime 연결은 미실시다.

보스 6상태 배경 제거 시도 2회는 모두 RGB 체크무늬로 반환됐다. 실제 알파가 없어 부적합. 생성물은 모델 출력 위치에 보존하고 승인 atlas에는 넣지 않는다. 투명 보스와 모션 정렬이 남아 있어 ASSET_READY가 아니다. 체크무늬를 투명인 척 보여 주는 화면을 만들지 않는다.

## 17 · 구현 연결과 저장 계약

현행 reusable anchor: src/production/runtime/enemy_action_scheduler.gd의 현재 행동/확정 경계, src/production/skill/production_skill_session.gd의 checkpoint/rollback 경계, 기존 LINE 형태 bag과 HOLD, CHAIN 매처/낙하. 이는 사용 가능성이지 새 규칙이 구현됐다는 뜻이 아니다.

새 data는 docs/design/autocast-r2-data.json에 격리한다. data/production, scenes/production, src/production은 지금 변경하지 않는다. 승인 후 별도 R2 rule_pack으로 통합하며 R1 저장을 값 이름만 바꿔 해석하지 않는다.

권장 저장 스냅샷: schema/rule_pack, 양 보드 셀·형태/자원 RNG·HOLD/NEXT, HP/armor/attack_bank, current action instance/ETA/extension_used, 선택 계열, chain_id/wave_index/category_snapshot/processed_event_ids. 중간 트랜잭션은 저장하지 않고 완료 경계에서 체크포인트. 전투 중 재시작 복구는 전체 원자 스냅샷 또는 명시적 전투 재시작 중 한 경로를 사용한다.

구현 순서: 데이터 검증 → unique-cell LINE 정산 → 파동 트랜잭션/자동 cast → 보스 scheduler/시간 cap → UI 세 상태(선택·다음·최근) → 승인 이미지 consumer → Godot 검증 → 사람 테스트. 별도 카탈로그·대시보드를 중복 생성하지 않는다.

## 19 · 남은 제작과 최종 승인 조건

방향 승인과 개별 이미지 승인은 별개다. 현재 완료 범위는 B안 상세화, 4타일 후보·Aseprite 패키징, 변경 규칙 검토 PDF 준비다. 전체 최종 블루프린트는 투명 보스·전투 구성 화면·모션 상태 검수·변경된 튜토리얼 fixture와 실행 인계 통합 후 발행한다.

보스 alpha 수정은 현재 이미지 모델 결과가 반복 실패했다. 자동으로 다른 유료 서비스나 무허가 후처리 도구를 도입하지 않는다. 원본은 보존한다. 최종 투명 PNG가 검증되기 전 기존 보스를 제거·대체하지 않는다.

이 문서의 상세 수치는 첫 구현용 권장 seed이지 플레이 검증 수치가 아니다. 구현 승인 전 상세 규칙·자산 준비를 완성할 수 있지만, 실제 Godot 동작·재미·기기 가시성까지 미리 승인됐다고 적지 않는다.
