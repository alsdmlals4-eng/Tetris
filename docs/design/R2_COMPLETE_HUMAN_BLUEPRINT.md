# R2 통합 사람용 블루프린트

## 01 · 승인 검토를 위한 한 권

테트리스로 준비하고 체인의 연쇄로 싸우는 단일 보스 퍼즐 전투. 네 문양은 공격·방어·치유·시간이며, 화면 왼쪽은 하나의 퍼즐, 오른쪽은 보스·공유 타이머·플레이어·스킬이다.

이 문서는 승인된 B안을 구현 가능한 단위로 연결한 통합 검토본이다. 방향 승인을 수치·이미지·실행 승인으로 확대하지 않는다. 최종 검토 후 구현을 시작한다. 현재 게임 코드에는 새 규칙을 적용하지 않았다.

읽기: 02~09 화면과 플레이 → 10~20 상세 규칙 → 21~27 데이터·모션·아틀라스 → 28~33 SWOT·구현·검증. 각 화면은 실제 후보 이미지를 사용한 설계 투영이며 Godot 실행 캡처가 아니다.

현재 책임 원본: 핵심 규칙 REPLANNING_AUTOCAST_R2.md, 추가 세션·자산·학습 배치 r2-complete-session.json, 이 문서는 통합 설명·준비 범위·수용 기준. 이전 R1·20쪽 개정 PDF는 과거 검토 증거로 보존한다. 이 통합본이 그 문서의 미완료 상태 안내를 대체한다.

## 02 · 세계와 플레이어의 역할

균열이 번지는 요새의 전선. 플레이어는 뱅가드 직업의 전투원을 조종해 균열 파괴자를 저지한다. 뱅가드는 직업명이지 게임 제목이 아니다. 화면의 문구는 작업 표기이며 별도 브랜드 로고를 임의 확정하지 않는다.

LINE에서는 다음 전투에 실을 자원을 준비하고 CHAIN에서는 선택한 전술을 연속 실행한다. 적은 읽을 수 있는 예고 행동을 반복한다. 긴급 방어·회복과 공격 준비 사이에서 선택하는 것이 첫 세션의 중심 경험이다.

첫 구현 범위는 메인·안내·연습·표준/여유 모드 단일 보스 전투·설정·결과·재도전. 캠페인, 상점, 장비 파밍, 추가 직업, 온라인, 과금, 최종 타이틀 브랜딩은 이번 범위에 억지로 포함하지 않는다. 이후 콘텐츠 확장과 미완료 준비 작업은 구분한다.

## 22 · 일반 전투의 첫 수치

@encounter

일반 전투 시작 HP100 / 보스HP240 / 공격가산0 / 방어도0 / 방벽0. LINE 활성, ATK 선택. 행동은 표 순서로 반복하며 각 실행 instance는 run_id와 증가하는 번호로 식별한다. 이름이 같은 망치 견제 두 개를 같은 행동으로 취급하지 않는다.

여유 모드는 준비시간만1.25배, 피해·보상 동일. 피해 없이 쉬는 행동은 안정 자세만 유지하며 회복·피격음·가짜 공격을 발생시키지 않는다. 42초 주기당 예정 피해59는 방어 전 계산이다. hp0 이외에 숨겨진 시간제한은 없다. 모든 값은 플레이 테스트 전 권장 seed다.

## 23 · 생성·입력·복구 상세

초기 CHAIN과 보충은 네 문양 균등 난수, 초기 보드만 즉시 매치를 거부하고 유효 교환을 확인한다. 초기/교착 해소 후보는 최대256회 탐색 후 검증된 학습 보드의 교환 전 배치를 무보상 fallback으로 쓴다. 일반 보충에는 학습용 stream을 사용하지 않는다. shape/resource/chain 각각 독립 RNG 상태를 저장한다.

LINE은 기존 회전·충돌·lock delay 구현의 계약 테스트를 통과하는 구조를 재사용한다. 입력 추천값 DAS150ms·ARR50ms·lock500ms·lock reset15회. 첫 보스 동안 자연 낙하1초/칸 고정. 숫자는 R2 데이터에 명시하고 자동 난도 상승은 제외한다. 활성 조각은 보드 전환 중 내려가지 않지만 보스 ETA는 흐른다.

키보드 LINE: 방향/A,D 이동, Z/X 회전, 아래/S 소프트드롭, Space 하드드롭, C HOLD. CHAIN: 방향 커서, Enter 선택·인접 교환, 마우스 두 칸 선택. 공통 Tab 전환, 1/2/3 계열, Esc 정지, F1 상세. 재지정 시 충돌 안내·초기화 제공. 패드는 데이터의 별도 매핑을 따른다.

저장은 user://replanned_r2/save.json, schema r2-save-v1. 임시 파일에 완전한 JSON과 checksum을 쓴 뒤 원자 교체, 이전 한 개 보존. 일반 전투 autosave는 안정 보드·트랜잭션 완료 경계만 사용한다. 중간 연쇄 종료 요청은 pause 상태에서 계속/직전 체크포인트로 메인 선택. 손상 저장은 부분 복원하지 않고 백업→실패하면 새 도전 안내. R1 저장은 읽기만 하고 R2로 자동 변환하지 않는다.

## 26 · 모션 연결 명세

| 상태 | 진입·길이 | 표시 | 게임 효과 |
| --- | --- | --- | --- |
| idle | 일반 대기 | 2.4초 호흡 scaleY 1~1.012, pivot 고정 | 없음 |
| anticipation | 견제 마지막0.6초 / 강타1.2초 | 준비 pose, 위협 문구 유지 | 아직 피해 없음 |
| impact | ETA0의 해결 이벤트 /120ms | 타격 pose, 최대4px 충격 이동 | 이미 확정된 피해 결과만 표시 |
| recovery | impact 후240ms / 안정 행동은 전 시간 | 복귀 pose | 안정 행동에는 타격 없음 |
| hurt | 유효 피해 시100ms | 피격 pose | 중복 피해 없음 |
| defeat | 보스HP0 이후 유지 | 패배 pose | 후속 공격·파동 취소 |

우선순위 defeat > impact > anticipation > hurt > idle. recovery는 공격 표시의 후속 구간이며 연속 피해로 준비 pose를 덮지 않는다. 연출 감소는 이동·호흡을 끄고 같은 시각에 정적 pose와 결과 텍스트를 표시한다. pause는 호흡·표시 타이머도 정지한다. 이 방식은 키 포즈+트윈이지 새 중간 그림을 그린 부드러운 프레임 애니메이션은 아니다.

## 31 · 검증·실험·완료 조건

@rule 18

정적 검사: 모든 후보 hash/region·실제 alpha·PDF exact source·데이터 범위. 자동 검사: 고정 교환/보충 결과, 중복 event, 시간 한도, DEF 대상, 저장 roundtrip. 실행 검사: 메인→출격→LINE→CHAIN→결과, pause/장치 이탈/재시작, 1280/1920/글꼴125%. 사람 검사: 역할 설명·위협 예측·자동 발동 이해·전환 부담. 앞 단계 PASS로 뒤 단계 PASS를 대체하지 않는다.

## 32 · 사운드·성능·실패 정책

첫 구현은 기존 적법한 project audio가 실제 재사용 가능한지 확인하고, 없으면 무음 모드로도 기능을 모두 이해할 수 있게 한다. 신규 음악·성우·유료 음원을 필수 의존성으로 넣지 않는다. 제작 대기 사운드는 게임 규칙이나 승인 블루프린트 해독을 막지 않는다.

이미지는 atlas별 한 번 로드, 매 프레임 파일 읽기/생성 금지. 입력·매처와 표시를 분리해 애니메이션 품질을 낮춰도 판정 유지. 연출용 객체는 재사용하고 메시지 로그는 최근100개로 제한. 60fps 목표는 구현 후 실제 장치 측정 항목이며 현재 성능 PASS가 아니다.

트랜잭션 실패 시 보드·자원·계열·행동을 체크포인트로 함께 복원하고 오류 pause. 데이터/자산 누락 시 잘못된 캐릭터로 대체하지 않고 명확한 개발 오류 표식. 출시에 오류 표식이 남아 있으면 출시 차단.

## 33 · 최종 승인과 증거 범위

이번 준비 범위: B안 규칙·세션 데이터·고정 튜토리얼·화면 아틀라스·4타일/얼굴/아이콘/환경/투명 보스·키 포즈 모션 명세·구현 단위·검증 기준을 한 권에 통합한다. 수치와 외형의 최종 사용 결정은 사용자 검토 대상이다. 이후 Godot 구현·플레이/접근성·배포/권리 검증은 승인 후 단계이며 지금 완료됐다고 적지 않는다.

실제 조사: Pillow alpha/합성 API, Godot AtlasTexture, 기존 SEGA 스킬 전투·Xbox 접근성 원칙. 단순 색 삭제는 핵의 흰색을 손상시켜 REJECT, 밝은 배경 연결요소와 보라색 핵 주변 보호를 결합한 국소 추출을 ADAPT, 새 유료 서비스 도입은 REJECT. 이 추출기는 현재 boss source 크기만 허용하며 다른 그림에 무검증 적용하지 않는다.

기술 원출처: https://pillow.readthedocs.io/en/stable/reference/Image.html · https://docs.godotengine.org/en/stable/classes/class_atlastexture.html . 게임 비교 원출처와 ADOPT/ADAPT/REJECT 판정은 REPLANNING_AUTOCAST_R2.md 20절을 함께 읽는다.

정확한 PDF source/hash, 전 페이지 렌더 검수, 테스트 결과와 원격 main readback은 통합 발행 receipt에서 확인한다. 자동 검증·문서 검토·사용자 승인·인게임 적용을 서로 구분한다. Base9.4.4 고정은 유지하며 공용 규칙으로 무리하게 승격하지 않는다.
